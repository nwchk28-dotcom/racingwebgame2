# APEX ONE

1台で走る、オンボード視点のフォーミュラ・タイムアタックです。2025年のF1カレンダーから立体交差のある鈴鹿を除いた23コースとセパンの計24コースを選べます。車体と周辺施設は独自のデザインです。

## Webアプリとして起動

このゲームはWebアプリ専用です。通常のブラウザではインストール案内を表示し、走行できません。

iPhone/iPad: Safariの共有 →「ホーム画面に追加」。表示される場合は「Webアプリとして開く」をオンにします。Android: Chromeの︙ →「ホーム画面に追加」→「インストール」。PCはChrome/Edgeのインストールアイコン、MacのSafariは「ファイル」→「Dockに追加」。追加したAPEX ONEのアイコンから起動してください。開発用localhostでも通常タブは案内画面になります。

## ローカル実行

```sh
npm ci
npm run dev
```

`npm run build` で静的ファイルを `dist/` に作成します。`npm run test` で周回判定を確認できます。

## 操作

- スマホ: 横向きにして、左の操舵ボタン、右のペダルで運転。スタート画面でスライダー式にも変更できます
- PC: A/D または左右矢印で操舵、W/上矢印で加速、S/下矢印で制動
- Esc: 一時停止、R: スタート地点にリセット
- 右上の音符ボタン: エンジン音のオン・オフ
- スタート画面でコースを選択。一時停止画面の「SELECT CIRCUIT」から戻れます

縁石の外端まではコース内です。4輪すべてが外に出るか、逆走、外周の円形ガードレールへの接触があった周回はベストタイムに記録されません。コースアウトしてもグリップや加減速は変わりません。記録はコース別にそのブラウザの `localStorage` に保存されます。NOVAは選択肢から削除しましたが、ブラウザに保存済みの旧記録は消去しません。

## セクターとギャップ

F1公式図と同じ区分でS1/S2/S3を計測します。区間下にそのコースの自己ベスト周回との差、GAP TO PBに同じ地点での累計差を表示します。緑のマイナスが先行、赤のプラスが遅れです。前周の値には「前周」と表示します。

旧記録に区間データがない場合、ベストタイムは維持し、次の自己ベスト更新までギャップは「—」です。区分と出典、近似位置の限界は[セクター資料](SECTOR_REFERENCES.md)を参照してください。

## コース形状

実在24コースの中心線は [bacinger/f1-circuits](https://github.com/bacinger/f1-circuits) のMITライセンスのデータを加工したものです。出典とライセンス全文は [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) に記載しています。距離は公式値に合わせ（セパンは5.543 km）、元データの座標が計時線と異なる上海などは周回原点を補正しました。全24コースの周回方向と最初の主要コーナーの左右を検証しています。シンガポールは元データの逆回りを修正したため、旧記録を保持したまま新しい保存キーで計測します。スタート位置と壁の範囲は公開コース図を参照した近似です。すべて現行の平面路面モデルで走行でき、高低差や正確な路面勾配、施設配置は再現していません。公式のコース図やロゴはゲーム内に収録していません。

道幅はFIAの基準幅と運営者・主催者の公開資料を参照して設定しています。セパン16〜22 m、上海通常14 m・T13付近20 m、バクー7.6〜13 mの幅変化に対応し、描画と壁・全輪コースアウト判定を共通化しました。車体横幅も約2 mに合わせています。区間別の実測データがない部分は近似です。[コース別設定・出典・再現の限界](TRACK_WIDTH_REFERENCES.md)を参照してください。

## エンジン音

実車のエンジン録音を使用しています。音源は [Edvvc / Ed Pond, “Red-Bull-Cosworth-STR1-2006-David-Coulthard.ogg”](https://commons.wikimedia.org/wiki/File:Red-Bull-Cosworth-STR1-2006-David-Coulthard.ogg)（[CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/)）。Goodwood Festival of Speedでのコース脇からの録音で、オンボード録音ではありません。Wikimedia CommonsのMP3変換版を収録し、再生時に異なる回転域の安定した区間から3つの波形を作ってブレンドします。録音の時間経過は再生せず、車速とギアから音程を決め、アクセル負荷で音色を変えています。音源ファイルとその改変部分はCC BY-SA 3.0で利用できます。

リポジトリをGitHubへプッシュし、Settings → Pages → Build and deployment → Sourceを **GitHub Actions** に設定してください。`main` へのプッシュでテスト、ビルド、公開が実行されます。`vite.config.ts` がリポジトリ名に合わせて公開パスを設定します。バックエンドは不要です。

### 走行条件を変更する更新と自己ベスト

`src/recordVersions.ts` の `RECORD_VERSIONS` で記録の互換性を管理します。

- 物理モデル、最高速度、グリップ、ダウンフォース、操舵、周回の有効判定など、全コースのタイム更新に影響する変更では `global` を1増やします。
- コース形状、道幅、壁、スタート／セクター位置など、特定コースのタイムに影響する変更では `tracks` の該当IDを1増やします。例：`tracks: { monza: 1 }`。複数コースを指定できます。
- UI、音声、外観だけの変更では増やしません。数値を減らしたり、過去の数値を再利用したりしないでください。

更新されたWebアプリを読み込むと、変更対象のPERSONAL BEST・セクター記録・ギャップ用走行履歴がまとめて未記録になります。新しい自己ベストは新バージョンで保存されます。旧記録は保存領域に残りますが、ゲームでは参照しません。初期値0は現在の記録を維持します。今回の管理機能追加自体は走行条件を変えないため、既存記録をリセットしません。

周回完了後は3秒間、前周の合計タイム・S1〜S3・自己ベストとの差を表示します。ベスト更新時の差は更新前のベストとの比較です。3秒後には次周の現在の計測値へ切り替わり、未通過セクターは未計測表示になります。表示保持中も次周の計測は続きます。初記録・無効ラップでは合計ギャップを表示しません。

### スマホの発熱・電力対策

スマホ・PCとも描画は最大60fpsを目標にします。描画解像度は軽量化前の設定（スマホはピクセル比最大1.35、PCは最大1.8）とMSAAを復元しています。スマホのHUD背景ぼかしは無効です。HUDと現在地マップは毎秒20回更新し、変わらない文字を書き換えません。走行計算とラップ判定は従来の固定120Hzを維持します。

メニュー・一時停止・縦向き案内では継続描画を停止し、画面変更時だけ描画します。非表示時は走行を一時停止します。消音・一時停止・メニューではAudioContextを停止し、発振器とフィルターの処理も止めます。記録の互換性は維持するためPBのリセットはありません。

低電力モードでもゲーム側の上限は60fpsです。ただしOS・ブラウザーがフレームの通知自体を制限する場合や処理能力が不足する場合、60fpsは保証できません。解像度・MSAAの復元により軽量化時よりGPU負荷は増えます。実機の温度・消費電力の削減量は未測定です。

添付のオンボード写真を参考に、カメラを高さ2.05m・車体ローカルZ=-0.55m・縦視野角40度へ変更しています。従来より車体とハロを大きく映し、中央の上半分を前方路面に割り当てます。視界変更に伴い、全コースの記録バージョンを1へ更新します。

車体はハロと中央支柱を取り外し、前後タイヤ幅を約40cm（以前の約27cmから約1.5倍）に変更しました。リムとタイヤ側面のリングも幅に合わせています。車幅は2mを維持し、全輪コースアウト判定は新しいタイヤ幅に合わせます。視界と縁石への接触条件が変わるため、全コースの記録バージョンは2です。

タイヤ直径は約6%縮小（1.04m→0.98m）し、接地位置を保つよう車軸高とリム・側面リングも調整しました。サイドポッドは幅と左右への張り出しを増やし、車幅2mの範囲内に収めています。今回の変更は外観の調整で、走行性能・接触／コースアウト判定は維持し、自己ベストはリセットしません。

タッチ操作はPointer Eventsを即時受付し、Touch Eventsを独立した補助入力として併用します。捕捉失敗・複数指・画面外での指離し・入力終了イベントの欠落を考慮しています。左右ボタンは縦方向を広げ、押下時の移動をやめました。ラップ数は表示せず、タイム表示の上部を詰めています。操作受付の変更に伴い全コースの記録バージョンは3です。

音声はbalancedバッファを使い、OSによる中断からの復帰を試み、操作時にも復帰を促します。再開失敗時の毎フレームの再試行は抑制します。シフト音量効果には車速3km/hのヒステリシスを設け、音量の回復は描画に依存しないオーディオクロックで予約します。音程の車速依存は維持します。実機のすべての音切れ・入力不具合が解消することは未検証です。

## iOS版の地形・操作UIへの更新

FormulaWorldIOS の Core が生成する路面高さ、勾配、バンクと、承認済みの `.corridor` のガードレール・退避路を Web 側へ取り込みました。コースデータは選択時に読み込みます。路肩に出ても路面の姿勢を連続して計算し、実際のガードレール位置で接触を判定します。走行条件が変わるため記録バージョンを4へ更新し、全コースの旧自己ベストは新条件の記録から分離します。

メニューまたは一時停止画面の「ボタン配置を変更」から、ハンドル・左右ボタン・ペダルを移動し、大きさと透明度を変更できます。「保存」で端末内に記憶します。

開発時は `npm run dev` を起動後、`/tools/preview.html` でインストール前の画面確認ができます。通常の公開入口は従来どおりホーム画面から起動するWebアプリ用です。

iOS側のデータを再同期する場合は macOS で `sh tools/sync-ios-circuits.sh` を実行します。隣の `FormulaWorldIOS` は読み取り専用で参照し、Web側の生成JSONだけを更新します。再同期で走行条件が変わる場合は記録バージョンも更新してください。

### ボタン配置と上下振動の修正

配置編集画面でも実際の走行用コントロールを使用し、表示・当たり判定・拡大率を一致させています。初期配置へ戻す操作とキャンセルは、保存するまで元の設定に影響しません。画面の端では拡大後のボタン全体が収まるように補正します。

車体は120Hzの物理状態間を描画時に補間し、人工的なカメラの上下振動を廃止しました。路面のサンプル境界では共有する法線を補間し、勾配・バンクによる姿勢の段差をなくしています。この勾配補正は重力による加減速にも影響するため、記録バージョンを5へ更新し、全コースの旧自己ベストを新条件の記録から分離します。

### 勾配での接地点の飛び・鈴鹿の誤判定・浮いた外周フェンスの修正

前回の経路ヒント付き検索は「距離の差が50cm以内なら前の進捗に近い点を優先」していたため、登坂中の接地点が止まってから飛び、鈴鹿では別の交差区間へ切り替わる場合がありました。現在はまず前後80m以内の連続した道路区間を選び、その中で幾何学的に最も近い点を正確に求めます。路面・四輪・周回計測が同じ区間のヒントを共有します。勾配上の10cm刻みの接地追跡と、鈴鹿の上下両レベル・左右3mの走行位置で回帰テストを行っています。

外周フェンスの高さを0に固定する処理をやめ、iOS版から地形グリッド・土手の接続点・外周フェンスの接地高も取り込みました。路側ガードレールの足元から周囲の地面まで土手を接続し、鈴鹿の橋区間では土手がアンダーパスに入り込まないよう除外しています。樹木・建物も描画地形に接地させています。走行・判定の修正に伴い記録バージョンは6となり、旧自己ベストは新条件から分離します。

`npm run dev` 後の `/tools/contact-check.html` では、Spaの登坂と鈴鹿の上下の立体交差について、実際の車体・路面描画・接地・周回判定コードを使って経路を再生できます（運転操作の自動テストではありません）。

### 縁石とランオフでの連続した接地・ちらつきの修正

路面を中心線の最近傍点から近似する計算を置き換え、iOS版と同じ連続した曲面（中心線・法線のスプラインと逆写像）で、道路から縁石・ガードレールまでの接地高さと勾配を計算します。バンクとカーブの外側でも、この曲面のヤコビアンから姿勢と重力を求めます。タイヤと周回位置も同じ座標系を使います。

描画では、道路・白線・縁石・ランオフを重ならない帯に分割し、一つの曲面に隙間なく配置します。旧来の「道路全体の下の草地」「縁石の外まで重なる路肩」「地形と同じ高さの平面」を廃止しました。ガードレールの外の土手も同じ分割位置で接続し、遠景が同じ深度に接する箇所には描画上の優先順位を付けています。逃げ道の境界は描画優先度を明示しています。

全25コースで路面から両側ガードレール直前までの接地・進捗・勾配、境界帯の非重複、実メッシュへのレイで縁石の内外の表面数と高さを確認します。`/tools/contact-check.html` の「左／右の縁石を横断」で境界を横切る経路を再生できます。接地・勾配計算の変更に伴い、記録バージョンは7となり、全コースの旧自己ベストを新条件から分離します。
